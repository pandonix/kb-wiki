# 张佳圆

Multica 创始人，前 TikTok 工程师。INTJ 人格，连续创业者——做过 AI 搜索、AI coding 工具，最终转向 Multica，一个开源的 Agent 协作与编排平台。^[raw/articles/2026-06-11-人是最慢的节点还怎么管AI-Agent.md]

## 关键观点

### 人是 AI 原生组织的瓶颈
张佳圆认为，当前组织的产出效率瓶颈已经是人而非 AI/Agent——人的注意力带宽有限，同时只能处理 3-5 件事，而 Agent 可以并行做几十上百件。这个判断来自 Multica 4 人团队的实战经验。

### Agent 协作设计原则
- **三类角色**：所有 Agent 协作可归结为 Orchestrator（协调者）、Worker（执行者）、Validator（验证者）
- **最多两层**：人类多层组织是在做信息聚合，Agent 没有这个限制，建太多层级是「对人类低效组织的拙劣模仿」
- **同一 Agent 可泛化**：Orchestrator 和 Worker 不需要每个任务换新 Agent

### Agent idle 率
提出「Agent idle 率」（闲置率）作为衡量组织 AI Native 程度的指标。假设 Agent 可运行 24 小时，大部分人的 Agent 满载时间只有 2-3 小时，降低 idle 率是组织持续优化方向。

### AI 时代思考退化
担心 AI 大量介入后人的思考能力退化。每天刻意写 journal、先独立思考再做 AI 讨论，保留独立思考时间。认为「人的思考在 AI 时代是被低估的」——AI 给出的是 P50 的中位数结果。

### 快速决策优于完美决策
INTJ 的完美主义倾向在创业中需要克制。「即使快速做错误决策，也比缓慢做正确决策好——错误决策可以修整，犹豫会让整个组织卡住。」

### 招募标准：high agency
招人看自主能动性，不在意背景、专业、经验——「你再怎么强，也很难强过 Agent」。有 AI/Agent 作为杠杆，理论上能学会任何事情。

## 创业哲学
- Multica 命名源自 Multics（1960 年代贝尔实验室第一款操作系统）——Multics 失败了但启发了 Unix、Linux、iOS、Android
- 「如果 Multica 失败了，但它启发了下一代操作系统的诞生，这就是很有意义的事」
- 「速度不再是壁垒，所有团队都在高速迭代。你只要活得足够久，可能是你很大的壁垒」
