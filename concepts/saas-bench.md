# SaaS-Bench：Agent 真实办公能力评测

## 核心定义

SaaS-Bench 是 UniPat AI 发布的 Computer-Use Agent 评测基准，将 23 个真实开源 SaaS 系统通过 Docker 本地部署，保留完整前后端逻辑、数据库状态和业务约束，让 Agent 在真实工作环境中执行 106 个跨应用长程任务。其核心论点是：现有 Agent Benchmark 成绩与真实工作能力之间存在巨大鸿沟。

## 设计特点

- **真系统**：23 个开源 SaaS，非仿真环境（含 OpenProject、Twenty CRM、OpenEMR、Mattermost 等）
- **真实数据**：每个系统填充了真实业务数据——用户、项目、订单、文件
- **跨应用长程**：93.4% 任务跨 2+ 应用，53 个任务跨 3 应用；97.3% 文本任务操作步数 >100 步，最长 300+ 步
- **多模态**：纯文本任务 74 个，涉及多模态理解 32 个
- **六领域覆盖**：软件研发、业务财务、医疗管理、团队协作、农业供应链、独立媒体

## 评估指标

| 指标 | 含义 | 严苛度 |
|------|------|--------|
| Resolved Score | 全部检查点通过才为 1，否则为 0 | 极严 |
| Checkpoint Score | 按权重计算部分检查点完成比例 | 宽松 |

两个指标之间的巨大落差，恰好暴露了 Agent 最核心的问题：能推进中间环节，但几乎无法走完完整长程工作流。

## 核心结果（2026-05）

| 模型 | Checkpoint Score | Resolved Score |
|------|-----------------|----------------|
| Claude Opus 4.7 | 43.9% | 3.8% |
| Kimi K2.5 | — | 0% |
| Gemini 3.1 Pro | — | 0% |

最强模型 106 个任务只完整通过 4 个。Pass@3（同一任务跑 3 次，对一次算通过）比 Pass@1 提升约 8pp，说明执行极不稳定。

## 四种结构性失败模式

### 1. 长程衰减
即使每步通过率 95%，12 步全部通过概率仅 54%。所有模型通过率随任务推进单调下降，无一能在后半段维持前期表现。

### 2. 上游错误级联
一个 3% 权重的错误节点可导致下游 30% 权重损失。如：误将公司客户创建为个人客户，后续所有发票、付款、对账全部挂在错误实体下。

### 3. 缺少状态复核（意图 vs 状态断层）
Agent 在意图层面认为成功（"已修复"），但验证器在状态层面发现失败（页面上实际未改）。当前 CUA 框架缺少严谨的反思闭环——Agent 是不会检查自己作业的学生。

### 4. 路径依赖导致不稳定
同一任务三次独立运行，初始状态完全相同，分数可从 0.00 到 0.68。微小决策差异导致后续轨迹完全分叉，长程任务执行变成赌博。

## 结构性发现

- 跨应用数 1→4：平均分从 53% 降至 20%
- 检查点 ≤6 vs ≥18：平均分从 65% 降至 27%
- 「跨应用 + 轨迹长 + 细粒度验证」得分最低——恰是真实工作流最常见形态

## 范式启示

四种失败模式指向同一底层事实：当前 Agent 缺少对持久状态的有效推理能力、操作后的闭环验证机制、从错误中恢复的能力。这不是靠模型变大或加工程模块能解决的，而是当前 Agent 范式的天花板。

正在形成的共识：今天的 SaaS 是给人设计的，当 Agent 成为主要用户，面向人类的界面变成累赘。未来不是让 Agent 学会操作人类软件，而是软件本身要为 Agent 重新设计。
