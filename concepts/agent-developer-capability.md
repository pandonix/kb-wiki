# Agent 开发者的三维能力立方体

## 核心定位

**传统全栈构建的是确定性系统，Agent开发者"驯养"的是一个概率性的、非确定性的智能体，并围绕它构建一整套工程体系。** 核心工作流从 产品经理→需求→代码，转变成了 **深度使用→发现边界→构建数据/评测→优化框架→推动模型进化**。^[raw/agent/Agent岗位要求.md]

## 三维能力立方体

一个现代Agent开发者的核心能力可以概括为：**深度的模型认知、全栈的系统工程能力，以及将两者打通的评测与数据思维。**

### 第一维：深度的模型认知与驾驭能力（"读心"）

- **模型原理与决策机制**：理解Transformer架构、上下文窗口、注意力机制，以及核心Agent范式（ReAct、Plan-and-Execute）。关键是能预判模型在不同范式下的失败模式。
- **人机协作与交互设计**：从"编写确定性指令"转向"设计高质量的模糊指令"。包括Prompt Engineering、上下文工程、记忆管理、RAG、工具调用描述。
- **模型"训练感"与数据思维**：具备通过数据微调模型行为的意识。能识别模型短板，系统性地构造高质量训练数据（SFT、偏好数据）来修复问题，甚至参与RL的数据生产。

### 第二维：全栈的系统工程与构建能力（"搭台"）

- **Agent专用基础设施**：封装LangChain、OpenAI Agents SDK等框架，集成外部Agent产品。掌握Docker/K8s确保Agent运行在稳定、可复现的沙盒环境。
- **高性能与前端可视化**：Agent的"不可观测性"是致命问题，必须用TypeScript/JS开发调试工具，将决策过程可视化。关键链路可能需Rust编写核心组件。
- **工具定义与API设计**：Agent的能力上限由其工具决定。需设计简洁、鲁棒、让模型容易理解的API和工具描述方案。

### 第三维：以评测为轴的闭环迭代思维（"探路"）

- **严谨的评测体系设计**：从真实场景抽象出可量化、有区分度的多维度评测集。将"任务完成度"细化为工具调用准确率、代码可执行性等客观指标。
- **Bad Case驱动的数据闭环**：通过评测发现Bad Case→分析根因→针对性地构造高价值数据（补齐数据集、边界用例、对抗样本）→反哺模型训练。
- **系统性的实验与分析能力**：运行对比实验验证"新工具描述"或"新上下文管理策略"是否有效，分析改动引起了模型行为的哪方面变化。

## 两种Agent岗位的分工

| 维度 | 数据策略岗 | 平台工程岗 |
|------|----------|----------|
| 核心产出 | 高质量数据、评测集、Bad Case分析报告 | 内部集成框架、容器化服务、可视化调试平台 |
| 核心能力 | 从"使用"到"认知"再到"数据"的转化 | 从"理解原理"到"工程实现"的构建 |
| 关键技能 | Python、LLM原理、评测设计、数据工程 | JS/TS + Rust + Docker/K8s、系统集成 |
| 对AI工具的使用 | 深度使用以发现模型短板 | 理解协议进行二次开发和系统集成 |
| 本质比喻 | 定义"评测什么、怎么算好" | 打造"高效运行评测、集成工具"的平台 |

## 传统全栈 vs Agent开发者

| 维度 | 传统全栈 | Agent开发者 |
|------|---------|-----------|
| 思维模式 | 确定性领域，输入决定输出 | 非确定性领域，引导模型在概率空间输出 |
| 架构视图 | 前端-后端-数据库三层 | 数据→训练→推理→评测→数据 飞轮 |
| 驱动模式 | 需求驱动 | Bad Case驱动 |
| 质量标准 | 测试覆盖率 | 评测通过率（任务完成度、工具调用准确率、交互效率） |
| 核心工具 | IDE、Postman、DevTools | 评测平台、轨迹调试工具、数据构造/标注平台 |
| Bug修复 | 改代码 | 调整指令、优化工具描述、构造数据反哺训练 |

## 终极画像

Agent开发者不是纯软件工程师，而是 **模型驯养师+系统建筑师** 的结合体。三条核心能力线：
1. **读心**：能读懂模型的"脑回路"
2. **搭台**：能用全栈技术为模型搭建稳固、可观测的舞台
3. **探路**：能用数据和评测为模型进化指明方向
