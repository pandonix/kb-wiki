# AI 软件形态演进

## 核心判断：Coding 已死，软件生产民主化

代码变成执行载体，和硬件一样；人不再需要用代码思考，架构师/程序员的历史使命完成了。软件本身不会变革，但软件**生产**会变得非常民主化。^[
消耗了上百亿 Token后， 对于 Agent 时代软件构建、软件形态及未来发展的思考.md
]

## 软件形态的演变

### 静态固定形态 → 以意图为接口的灵活形态

Unix 哲学因灵活性复兴。软件的边界不再由代码结构决定，而是由意图（Goal）、约束（Constraints）、上下文（Context）决定。

### 中间市场被压缩

软件生态向"面向人"和"面向机器"两端集中：
- **面向人**：极致体验、人机协同
- **面向机器**：API、Agent Infra、Skill 封装

中间市场（不做 deep vertical、不做 platform 的 SaaS）被压缩。^[
消耗了上百亿 Token后， 对于 Agent 时代软件构建、软件形态及未来发展的思考.md
]

## 价值转移

价值没有消失，只是从"把功能写出来"转移到了"把复杂性组织起来"。稀缺资源从编码，转移到需求定义、流程重构、数据接入、治理、分发与信任。^[
起大早，赶晚集.md
]

## Skill 是最终形态吗？

不一定。Skill 是目前的较优抽象，但未来会出现更复杂的抽象，通过自然语言描述、人机协同生成，可 Debug 和分发。核心是蒸馏人类专家知识。

## 软件日抛化趋势

核心洞察：我们过去花几百万上 ERP，买的是矿机（软件），矿（数据）才是真正值钱的。AI 把挖矿成本从马拉松压缩到百米跑。^[
软件，真的会变成"日抛"吗？.md
]

- 实战案例：10 年 ERP 系统（306 张表、50 万条数据），AI 重建仅需 2 小时搭框架 + 1 小时迁数据
- 日抛化是方向而非截止日期：年抛/月抛/日抛三种形态会持续共存
- 数据战略优先于软件战略：先列数据清单（矿图），再决定系统策略

## 单位智能与模型分工

Agent 时代带来"不可能三角"：质量、速度、价格不可能同时极致。未来的 AI 工作流本质上是**复杂推理模型和日常任务模型的分工协作**。^[从 Hy3 preview 看 AI 下半场.md]

- Hy3 preview：中型模型（295B MoE）主动找效果-速度-价格平衡点，为日常 Agent 任务和规模化吞吐而生
- DeepSeek V4：Flash + Pro 双版本覆盖不同层级——Pro (1.6T, 49B active) 负责高难度推理，Flash (284B, 13B active) 为日常任务提供高吞吐低成本方案
- 共识：性价比正在变得比"性能最优"更重要
- 对软件形态的影响：应用开发不再依赖单一旗舰模型，而是按任务分发——"Context 工程"取代"模型选型"成为核心竞争力

### 可缩放工作台：软件形态的分层架构

DeepSeek-V4 的分层注意力架构（滑动窗口 + CSA + HCA）为软件形态提供了一个更深层的启示：**大规模系统的核心不是把所有东西平铺，而是分层+索引+压缩**。^[raw/papers/20260529T100332--paper-deepseek-v4.md]

软件从"一个窗口"演进为"一套工作台"：
- **近处**：保留原文、最新状态、关键约束（不压缩）
- **中层**：保留结构化摘要、决策、风险、下一步（压缩再检索）
- **远处**：保留概念索引、链接、反复出现的问题（粗粒度保留）

这与 [[agent-memory]] 中的压缩记忆地图理念一致，也与 [[harness-engineering]] 的分层上下文管理互补。百万上下文不是免整理，而是让整理后的多层环境有地方展开。
