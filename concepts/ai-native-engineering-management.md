# AI 时代工程团队管理

Anthropic Claude Code 团队工程与产品负责人 Fiona Fung 在 Code with Claude 2026 大会上的管理实践分享。核心主题：当「写代码几乎免费」，工程管理的旧规则全部需要重构。

## 瓶颈已转移

过去瓶颈是「写代码慢」，现在转移到了验证、评审、跨职能协作和安全性。所有旧流程都基于「写代码很贵」的假设设计，既然现在代码几乎免费，流程必须全部重构。

## 正在失效的旧流程

- 长达半年的产品路线图
- 繁琐的排期会议
- 对代码的所有权划分
- 马拉松式的代码评审会议
- 按部就班的传统团队结构
- 知识库分享
- 漫长的新人入职培训

## 少做什么

### JIT Planning（即时规划）

原型成本趋于零，「提前规划」的杠杆消失。什么时候需要再做什么。

### 设计文档退位

默认讨论媒介从「先写一份 doc」变成「先发一个 PR」。代码是唯一的 source of truth。

### 产品评审会减少

内部 dogfooding（ant-fooding），推给全员试用，而非评审 mock。

## 多做什么：Shift Left

把质量保障从交付端（人工测试）往源头（自动化）推。因为角色边界正在模糊（设计师也提交代码、PM 也提交 PR），传统人工 QA 根本接不住暴增的代码产出率。

## 技术辩论：从白板到三个 PR

「当写代码变得轻而易举，无休止的争论就显得极其昂贵。」让 Claude 同时搓出三个版本的 PR，直接对比完整代码实现。「决不能沦为谁最后一个 commit 谁赢。」

## 代码评审分工

| 交给 Claude | 人保留 |
|------------|--------|
| 风格检查、lint 去重 | 法律和合规审核 |
| 回应代码评审意见 | 安全敏感代码 |
| 抓常规 bug | 产品 sense 和品味 |
| 补全单元测试 | |

## 组织形态

- **尽量扁平**：所有小组共享一个团队 mission，目标一变层级越少越好
- **经理从 IC 做起**：所有经理必须先做一线工程师，不愿意的趁早分开
- **跨职能融合**：非技术人员也开始写代码，工程师也做传统上属于其他岗位的活

## 三个可观察的指标（和一个警告）

1. 新人爬坡时间显著下降
2. PR 生命周期明显变短
3. Claude 辅助提交覆盖比例越来越高

**警告**：别死盯着「有多少代码是 AI 写的」——吞吐量本身不是目的，关键看产品质量和可靠性。

## 三个未解决的问题

1. 工程师跨平台流转后，传统平台分队是否还有意义
2. 自动化评审要推到多远
3. 角色模糊后如何让所有人感觉同样有产出感

## 最后建议

「挑出极其折腾人、尤为啰嗦的那条工作流，重新审视一下它到底还在为谁干活。」
