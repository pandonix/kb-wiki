# 企业级智能体实践：从Copilot到数字员工

## 核心判断

**业界已经从"AI帮人写报告、回答问题"走到了"AI在明确岗位、明确权限、明确流程里完成一类工作"，但还没有普遍走到"AI自主制定商业目标、调配资源、承担经营结果"。** 真正靠谱的企业级智能体不是"没有人类"，而是：人设定目标和边界，智能体在边界内闭环执行，超出边界就升级给人。^[raw/agent/企业级智能体实践.md]

## 四层分级

| 层级 | 类型 | 是否算真正智能体 |
|------|------|:---:|
| L1 | 问答、搜索、总结、生成报告 | 更像 Copilot |
| L2 | 生成建议、草稿、分析，人来点击确认 | 半自动 Copilot |
| L3 | 在明确规则内调用系统、写回数据、发邮件、建工单、关闭工单 | **窄域智能体** |
| L4 | 自己判断商业目标、权衡风险、做重大经营决策并承担结果 | 目前基本没有成熟案例 |

## 典型实践案例

### Tata Steel + Google Cloud（最接近"企业大脑"）

在9个月内部署300+专用AI智能体，建立两个中枢：
- **Zen AI**：内部低代码平台，让员工构建专用智能体
- **Tata Steel Digital Assistant**：决策型 command center，查询多源信息（公共数据、内部系统、财务记录、SOP、通话录音、复杂PDF），叠加实时新闻、地缘政治情绪和大宗商品价格数据进行市场预测

成效：HR例行工单70%+自主解决，客户投诉处理时间降低50%，高风险区域视频流分析触发实时安全提醒。

### Microsoft Farmlands（采购运营智能体）

在Dynamics 365部署Supplier Communications Agent，处理供应商邮件、识别采购订单变更、更新PO、起草跟进邮件。处理50%采购订单相关邮件，每周节省20小时，正确理解70-80%相关邮件。关键商业变更（价格、数量、取消余额）仍标记为需要人工审批。

### Salesforce Agentforce（客服/销售/流程型）

- Engie：回答账单和清洁能源问题，协助83%用户
- 1-800Accountant：税务周自主解决70%聊天互动
- Hero FinCorp：部署自动化贷款处理，预计75% straight-through processing

### ServiceNow（最接近"真正数字员工"）

Autonomous Workforce / L1 Service Desk AI Specialist：端到端处理常见IT支持请求（密码重置、软件访问开通、网络故障排查），24/7工作，自行领取能解决的ticket，遵守审批链，为每个动作留下审计记录。但高风险动作（网络安全修复方案执行）仍需人工网络操作员批准。

## 当前成熟度

- McKinsey 2025：23%组织正在某些地方scale agentic AI，39%还在实验；任何单一业务功能里scale的比例不超过10%
- Gartner：40%企业应用将在2026年底集成任务型AI agents，但存在大量"agentwashing"
- 60-70%的"智能体"案例仍偏Copilot或半自动流程助手；20-30%已是窄域可独立工作的智能体

## 可以独立闭环的任务

HR常规工单、IT L1支持、密码重置、软件权限申请、采购催单、客服FAQ、客户分流、服务工单创建、简单取消/退改请求、订单状态查询、账单问题、知识库型支持。

## 半自动需人批准的任务

采购数量/价格变更、合同风险判断、供应商异常、网络安全修复方案、客户投诉升级、贷款/理赔异常项、财务分类边界案例。

## 很少真正交给AI独立做的

战略定价、年度预算、重大采购、市场进入/退出、裁员计划、并购、供应链重大切换、信贷政策改变、产能调整、法律责任较高的决策。

## CIO 视角："高频且痛"场景与生产级标准

2026年顺丰集团 CIO 刘潭仁和深信服 CIO 宋东林提出了更务实的生产级 Agent 评判标准。^[raw/articles/2026-05-29-深度对话-后龙虾时代企业Agent从能用到生产级差距在哪里.md]

### 场景选择：高频且痛

Agent 落地首先不是技术问题，而是场景问题：

- **"高频"**：需求常态化发生、使用体量充足
- **"痛"**：传统作业方式效率低下，业务端有强烈优化需求
- 二者兼备，Agent 项目才有立项价值

### ROI 计算

企业做 Agent 前需要算清：业务规模是否足够大，人力成本是否足够高，问题是否足够集中。但 ROI 只是第一层筛选，更隐性的条件包括：
- 问题是否真的适合用大模型解决
- 企业是否已有可用的数据和知识沉淀
- 业务团队是否愿意改变流程并认可这件事的价值

### 准确率对标人工

大模型天然存在幻觉，追求绝对正确成本极高且边际收益下降。评判标准应对标人工：
- 综合表现不低于普通员工
- 效率、输出一致性上更稳定
- 即具备落地价值

### 人机协作新模式

Agent 承担基础工作与初步判断，人工负责校验、决策与责任兜底。形成"Agent 做、人验证"的闭环。

### 数据知识治理是长期壁垒

随着大模型能力趋同，企业长期壁垒不是模型，而是不可轻易复制的数据、知识和业务理解。需要从"服务人"的知识结构重组为"服务 Agent"的可调用能力结构，并通过 good case / bad case 反馈持续优化。

详见 [[agent-data-governance]]。

## 靠谱的落地路径

1. **选高频、可验证、低到中风险的决策场景**（采购订单变更、库存补货建议、客服分流）
2. **先做"建议+执行草稿+人类审批"**（human-in-the-loop）
3. **建立统一数据层和权限层**（ERP、CRM、财务、合同、供应链、知识库的安全访问）
4. **把智能体当"数字员工"治理**（身份、权限、操作日志、审批边界、异常回滚、成本监控、效果评估）

## Agentwashing 问题

详见 [[agentwashing]]。核心识别标准：真正的Agent基于大模型推理处理模糊指令，遇到未预见情况能自我调整；Agentwashing产品（传统自动化）基于硬编码if-else逻辑，路径固定，一错就崩。
