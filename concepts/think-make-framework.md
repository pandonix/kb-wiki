# Think/Make 精力分配框架

## 核心命题

WquGuru 提出的 Agent 时代个人生产率模型：过去「思考 vs 执行」的二元模型需要重新校准。**执行仍然重要，但执行形态从亲手完成转变为编排式执行——定义目标、拆解约束、配置上下文、验证输出、整合交付。** 真正的问题不是「多思考还是多执行」，而是「当执行被 Agent 放大后，我该把自己放在工作链条的哪一层」。^[2026-05-27-Think-and-Make-Agent时代精力的重分配.md]

## 时间分配迁移

| 时期 | Make (执行) | Think (思考) | 特征 |
|------|-----------|------------|------|
| 过去最优 | 70% | 30% | 受限于自身执行带宽 |
| 未来 3 年最优 | 50% | 50% | 编排式执行 + 复合思维 |
| 少数人可达 | 40% | 60% | 需深厚领域积累和外部反馈 |

这里的 Make 不再只是亲手完成任务，而是**编排式执行**：编排 Agent、设计工作流、验证输出、完成最终交付。Think 也不只是坐着空想，而是**复合思维**：判断什么值得做、设计系统来做、复盘 Agent 为什么做错、把经验沉淀成更强工作流。^[2026-05-27-Think-and-Make-Agent时代精力的重分配.md]

## 为什么旧模型失效

在没有 Agent 的时代，一个人的产出受限于执行带宽——每天能写多少代码、读多少材料、做多少分析。70% Make / 30% Think 是强默认策略：做得多，反馈多，学习快。

Agent 改变了这个约束。麦肯锡 2025 年全球 AI 调研显示：AI 高绩效组织的区别，除了用了更多模型，更重要的是**主动重写 workflow**。价值正在从「会问 AI 一个问题」进入「能把一段工作改造成 AI 可以持续参与的系统」。^[2026-05-27-Think-and-Make-Agent时代精力的重分配.md]

低层执行被压缩，高层执行变得更值钱：
- 把模糊目标翻译成 Agent 能执行的任务
- 给 Agent 足够上下文，同时控制噪声
- 设计检查点，让错误在早期暴露
- 对输出做质量判断，避免照单全收
- 把一次成功流程固化成可复用系统

## 五种人的重新排序

| 类型 | Make:Think | 风险/机会 |
|------|-----------|----------|
| 纯执行者 | 95:5 | ⚠️ 最危险：重复执行可被 Agent 替代，议价权下降 |
| 传统高效者 | 70:30 | ⚠️ 仍强但错过杠杆：只把 AI 当加速器，没重写工作方式 |
| 新平衡者 | 50:50 | ✅ 最优：闭环优势，Make→Think→系统化 Make |
| 深度思考者 | 30:70 | ⚠️ 上限高但风险大：易退化为高质量拖延 |
| 任务定义者 | 迁移中 | ✅ 自救方向：从任务承接者升级为任务定义者 |

70:30 人群的典型信号：每天用 AI，但只把 AI 当加速器，没有沉淀项目级 coding workflow、没有建立事实核查和来源分层、没有重新设计每周的产出系统。^[2026-05-27-Think-and-Make-Agent时代精力的重分配.md]

## 与 PACT 的关系

Think/Make 框架是 PACT 方法论在 Agent 时代个人生产率上的具体化：
- **P**urposeful：先判断什么值得做
- **A**ctionable：把模糊目标翻译成 Agent 能执行的任务
- **C**ontinuous：把交付复盘成下一次更强的工作流
- **T**rackable：用可观察的 Make 检验 Think
