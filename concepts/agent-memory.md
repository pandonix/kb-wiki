# Agent 记忆系统

## 核心问题

大多数智能体活在「失忆式工作」模式：每次检索从零开始，推理路径无法沉淀，失败不转化为经验。记忆在增长，智能却没有。^[新一代记忆智能体框架MIA.md]

## Hassabis 的视角

- 当前把所有东西塞进上下文窗口的做法是"用胶带糊住的临时方案"
- 百万 token 上下文窗口处理实时视频只够 20 分钟
- 即使存储无限，检索真正需要的信息成本不可忽视
- 记忆领域还有很大创新空间——他博士研究的就是海马体如何将新知识优雅地整合进已有知识库
- 大脑在 REM 睡眠中回放重要经历来巩固学习，DeepMind 的 DQN 就借鉴了"经验回放"机制

^[Demis Hassabis：AGI 还缺什么.md]

## MIA 框架：Memory Intelligence Agent

上海创智学院 + 华东师范大学联合提出，面向深度研究场景的记忆智能体框架。

### Planner–Executor–Manager 架构

| 角色 | 职责 |
|------|------|
| Planner | 战术大脑：制定研究计划，通过测试时持续学习实时调整策略 |
| Executor | 执行专家：解读并遵循复杂研究蓝图 |
| Manager | 终极管理员：优化记忆存储，消除冗余 |

### 双记忆机制

- **非参数记忆**：沉淀经验（结构化存储历史轨迹）
- **参数记忆**：吸收能力（在线更新 Planner 参数）
- 两者相互转化，形成持续进化的闭环

### 三维检索机制

1. 语义相似度（保证相关性）
2. 价值奖励（偏好高质量经验）
3. 频率奖励（激活长尾知识）

额外引入失败轨迹作为约束——记忆既能提供参考，又能避免重复错误。

### 交替强化学习

- 阶段一：固定 Planner，让 Executor 学会理解并严格执行规划
- 阶段二：固定 Executor，让 Planner 学习利用记忆生成更优计划 + 反思重规划

解决"规划很好，执行跟不上"的问题。

### 测试时持续学习

推理阶段不再冻结模型：
- 执行任务时生成多条候选路径
- 从成功/失败路径提取非参数化记忆
- 基于成功路径在线更新参数化记忆
- 推理与训练几乎同步，真正的在线学习闭环

### 自进化评估机制

用「过程质量」替代「结果标签」：
- 逻辑评审员：检查推理链条自洽
- 事实评审员：验证信息来源、检测幻觉
- 结果评审员：评估任务完成度
- 领域主席：综合决策

### 实验结果

- 7B 执行器的 MIA 超越不调用工具的 GPT-5.4 / GPT-4o / Gemini-2.5-Pro
- 在 7 个核心数据集上均取得当前最佳记忆方法性能
- 基于 Qwen-2.5-VL-7B 逼近 Gemini-3-Flash

## 从记忆到能力的关键跃迁

智能体记忆不应只是记住"结果是什么"，而应学会"该怎么做"。决定一个智能体上限的，不再仅仅是它接入了多少外部工具，而是它能否在每一次交互中，将繁杂的「过程信息」压缩为精炼的「执行本能」。

## 压缩记忆地图：DeepSeek-V4 的启示

DeepSeek-V4 的长上下文架构（CSA/HCA）为 Agent 记忆系统提供了一个可迁移的蓝图：记忆不是把所有材料平铺给模型，而是按距离和任务相关性分层。^[raw/papers/20260529T100332--paper-deepseek-v4.md]

| 层级 | 对应记忆 | 压缩策略 |
|------|----------|----------|
| 近处（当前任务） | 原文、最新状态、关键约束 | 不压缩，保留细节 |
| 中层（近期项目） | 结构化摘要、决策、风险、下一步 | CSA 式压缩再检索 |
| 远处（长期框架） | 概念索引、链接、反复出现的问题 | HCA 式粗粒度保留 |

这印证了一个核心判断：**百万上下文不是免整理，而是让整理后的多层记忆有地方展开。** 上下文越长，越需要压缩、索引和分层。粗暴塞全文只能把成本和注意力噪声一起放大。^[raw/papers/20260529T100332--paper-deepseek-v4.md]

## 灾难性遗忘：后训练阶段的知识丢失

AI 失语现象揭示了 Agent 记忆系统的另一面——**后训练阶段的灾难性遗忘**。模型在预训练阶段学到的知识（如长尾人物名），在后训练阶段因稀疏暴露而被高频 token（工具调用、代码符号、安全拒答模板）挤压输出通路。^[raw/articles/2026-05-29-AI为什么会失语.md]

关键启示：
- 模型"知道"不等于"能稳定调出"——评估 Agent 记忆时需区分内部表示和输出通路
- 低频 token 的连接强度需要最低限度的训练机会来维持
- 这与 MIA 框架中"频率奖励"机制的目标一致：激活长尾知识
- 对 Agent 系统的工程含义：维护 Agent 记忆时，高频使用的知识会自然强化，但低频但重要的知识需要主动保护

## Memory 驱动开发实践

在实际 AI 编码中，「Memory 驱动开发」是提升代码采纳率的核心原则：大模型没有中期记忆，严重依赖上下文信息。AI 生成代码的质量直接取决于输入的准确性和完整性。^[如何将 AI 代码采纳率从30%提升到80%？.md]

关键实践：
- **原子化任务**：将复杂需求拆解为单一职责的小任务
- **精准上下文**：确保每个任务都有完整、精准、简洁的上下文
- **结构化表达**：使用清晰的结构化语言描述需求和约束

这与 [[context-engineering]] 中的分层上下文管理直接相关。

## 与 Skill 的关系

Skill 蒸馏静态知识，MIA 积累动态经验——两者互补。Skill 是 L1 精度的确定性注入，MIA 的参数记忆更新则试图捕捉隐性能力。
