# 人货场视角下的银行金融服务

将零售业"人货场"框架应用于银行业，跳出产品本位的传统视角，从互联网/零售角度重新拆解金融服务。框架适合**重构用户体验和前端运营**，但不能替代银行作为风险经营者的本质思考。

## 人：从"客户分层"到"用户经营"

传统银行看"人"按 AUM 做静态分层。人货场视角下重定义为：

- **生命周期阶段** — 学生→职场→成家→子女教育→退休→传承，每阶段金融需求结构差异极大
- **行为画像** — 不是"他是谁"而是"他在做什么"，行为决定需求
- **关系网络** — 家庭账户、企业主与公司账户、上下游供应链，银行的真正客户单位可能是一组关系

转变核心：从"客户是被服务的对象"变成"用户是需要被经营的资产"，关心 LTV、留存、激活、流失预警。

## 货：金融产品作为 SKU

- **手段 vs 目的** — 用户买理财的目的不是"持有产品"而是"让钱增值/为某目标储蓄"，目标型理财比按收益率排序的货架更有粘性
- **标品 vs 非标品** — 存款/基金/保险是标品（竞争靠价格渠道），私行定制/并购融资是非标品（竞争靠服务能力）
- **货架运营** — App 首屏放什么本质是货架运营：高频引流款、利润款、形象款各有其位
- **组合而非单品** — 围绕场景（买房）的产品组合（房贷+寿险+财产险+装修分期）价值远高于单品

## 场：从网点到嵌入式再到 Agent 节点

传统银行的"场"极其贫瘠——网点、ATM、网银、App。但真实金融需求发生在各种生活场景中：买车、装修、旅行、创业、教育、医疗。

**用户不会因为"想用金融服务"才打开银行 App，而是因为"要做某件事"才顺带需要金融。**

两条路径：
1. **银行进入场景**（嵌入式金融 Embedded Finance）— 把金融能力嵌入其他平台交易流
2. **银行经营自己的场景**（超级 App）— 把生活服务拉进 App，让金融成为副产品

核心张力：银行擅长造金融产品，但场景主导权往往不在它手里。

## Agent 时代的人货场重构

当 Agent 成为默认的金融服务消费者：

- **人** → 用户 + 个人 Agent + 垂直场景 Agent 三层
- **货** → 从预打包产品变为原子化、可程序化调用的金融 API，支持 Agent 实时组装方案和动态定价
- **场** → 银行可能退到后端成为"金融界 AWS"，或推出自己的金融 Agent 做用户 CFO

银行需要回答的根本问题：**服务终端用户、服务个人 Agent、还是服务垂直 Agent？** 最危险的是三个都想做，三个都不深入。

## 双面 Agent 形态

银行可以构建同时面向 B2C 和 B2A 的 Agent：
- B2C 面：像金融管家，懂人、懂生活、懂场景
- B2A 面：像金融能力服务器，响应结构化协议、定价透明

两者共享同一套底层能力（金融产品库、风险定价引擎、合规框架），区别在接口形态和信任建立方式。参见 [[ai-native-bank|AI 原生银行]]。

## AI 原生银行四层架构

1. 金融能力 API 层 — 原子化金融服务
2. 风险与定价引擎 — 动态个性化定价
3. 银行自有金融 Agent — 非 chatbot，而是能与个人/垂直 Agent 协作的智能体
4. 用户和场景连接层 — 嵌入式 SDK + Agent 协议 + 自有 to C 入口
