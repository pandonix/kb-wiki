### 一、知识储备

**1. 大语言模型与 Agent 核心原理**
- **LLM 基础**：Transformer 架构、预训练/指令微调/RLHF/强化学习的基本流程，理解 `temperature`、`top-p` 等解码策略如何影响生成。  
- **Agent 工作机制**：深度掌握 **ReAct、Plan-and-Execute、Code-Act** 等范式，理解规划、工具调用（Function Calling）、记忆管理、多轮交互与指令跟随的实现方式。  
- **工具的底层表示**：了解工具描述 Schema 如何被序列化到 Prompt 中，不同模型对 system prompt、tool call 格式的敏感度，以及上下文窗口和注意力机制如何影响长程任务。

**2. 数据工程与标注策略**
- **语料设计原则**：知道如何构造“激发推理”的代码生成、多步规划、工具组合调用的 conversation 数据，能平衡难度、多样性与正确性。  
- **标注范式对比**：熟悉监督微调（SFT）数据、偏好数据（RLHF/DPO）、过程奖励（PRM）和结果奖励（ORM）所需的标注格式，清楚不同策略对 Agent 的“工具幻觉”“反复循环”等问题的影响路径。  
- **数据质量把控**：掌握程序正确性校验、沙盒执行验证、静态分析、人工审核流程，通过数据降噪来避免模型学到错误模式。

**3. 评测基准与指标体系**
- **评测集设计方法论**：懂得如何构建高区分度、防泄漏的测试集，能从“任务完成度、代码规范、工程质量、工具调用准确率、规划合理性”等多维度打分。  
- **关键指标**：理解 `pass@k`、任务成功率、工具调用精确率/召回率、错误类型分布，以及对 Agent 特别重要的“子任务完成率”和“环境交互步数”等。  
- **业界前沿**：持续跟进 SWE-bench、WebArena、GAIA、AgentBench 等基准，并思考其局限性，能够设计贴近真实用户场景的用例。

**4. 强化学习与能力可控性**
- **基础概念**：理解策略、奖励函数、价值函数，PPO、DPO、GRPO 等算法的大致差异。  
- **数据侧联动**：清楚 RL 训练中 “rollout 数据”如何采集、清洗和加权，能通过数据分析 reward hacking 或能力退化现象，提出数据侧的修正建议，如构建针对性惩罚样本或边界用例。

**5. AI 编程工具深度认知**
- 不只是“会用”，而是深入理解 **Claude Code、Cursor、OpenClaw** 的架构理念：它们如何构建上下文（如 repo map、代码索引）、如何结构 agentic loop、处理权限控制和用户确认、进行文件 diff 与应用修改。  
- 对 **代码生成特有问题** 的理解：如语法正确性、依赖幻觉、安全漏洞、破坏现有功能、测试覆盖不全等。

**6. 软件工程与系统能力**
- 代码规范、Git 工作流、CI/CD、容器化（Docker）执行环境搭建、大型项目的模块化设计，保证你的评测与数据流水线可靠、可复现。

这两个职位在同一支 Agent 团队里，但**职责泾渭分明**。简单来说，上一个职位是**数据与评测策略的“定义者”**，核心是思维和判断；而你这个新职位是**基础设施与平台的“构建者”**，核心是工程实现。

它们的核心区别可以这样理解：前者负责产出“评测什么、怎么算好”的标准和高品质数据，后者则负责打造能“高效运行评测、集成各类工具”的工程平台。

具体在能力栈上的区别，可以从这三方面看：

**1. 核心定位与产出物不同**
-   **上一个（数据策略岗）**
    核心产出是**高质量数据、评测集、Bad Case分析报告**。他需要深度用 Claude Code 去发现模型短板，然后设计数据去“修复”它。这是一种**从“使用”到“认知”再到“数据”**的转化能力。
-   **这一个（平台工程岗）**
    核心产出是**内部集成框架、容器化服务、可视化调试平台**。他需要把 Claude Code 这类工具**集成进内部系统**或进行二次开发。这是一种**从“理解原理”到“工程实现”**的构建能力。

**2. 知识深度与应用方向不同**
-   **相同点**：两者都需要深度使用 AI 编程工具，也都要懂 Agent 原理。
-   **关键区别**：
    -   **数据岗**利用这些认知去**设计评测维度**，发现模型在哪类工具调用上容易出错。
    -   **工程岗**则利用这些认知去**进行二次开发**，比如理解 Claude Code 的工具调用协议后，**写胶水代码**将其请求格式适配到内部的 RL 训练框架里。他还要解决**高并发和稳定性问题**，比如维护 Agent 容器服务，这与数据岗的关注点完全不同。

**3. 硬技能要求的核心差异点**
新职位有三个独特且“硬核”的技能要求：

-   **前端开发能力（JavaScript/TypeScript）**
    这是最明显的分水岭。数据岗完全不要求前端，而工程岗明确要独立开发前端功能（如轨迹查看、调试分析界面），目的是为算法团队提供可视化的“显微镜”。

-   **系统编程与高性能开发（Rust）**
    Rust 的出现，说明这个岗位可能需要处理 Agent 环境与仿真器交互、大规模数据流处理等**对性能和内存安全有极致要求**的核心组件，这在数据岗工作流中极少出现。

-   **基础设施与运维能力（Docker/Kubernetes）**
    数据岗只需简单用沙盒来做代码验证。而工程岗负责的是整个评测平台的**服务化部署与稳定性**，需要容器编排、资源调度和CI/CD流程的经验，工作成果是7x24小时在线的可靠服务。

这与传统开发“需求-编码-测试”的线性模式有本质区别。Agent开发更像是在“驯养”一个具备推理能力、但不可靠的数字大脑，同时为它打造一个强健的身体和感知环境。

以下是这个能力立方体的具体拆解：

---

### 第一维：深度的模型认知与驾驭能力

这是新时代Agent开发者的核心壁垒，即不仅仅把模型当工具，而是理解其“思维方式”和边界。

-   **模型原理与决策机制理解**：理解Transformer架构、上下文窗口、注意力机制，以及核心的Agent范式（ReAct、Plan-and-Execute）。关键是能预判模型在不同范式下的失败模式，比如何时会遗忘目标、产生幻觉或陷入死循环。
-   **人机协作与交互设计能力**：从“编写确定性指令”转向“设计高质量的模糊指令”。这包括精通Prompt Engineering和上下文工程，能动态管理记忆、检索增强生成（RAG）和工具调用描述，以构建可靠的Agent交互循环。
-   **模型“训练感”与数据思维**：具备通过数据微调模型行为的意识。能识别模型短板，并系统性地构造高质量训练数据（如SFT、偏好数据）来修复问题，甚至参与强化学习（RL）的数据生产，这是一种更高阶的驾驭方式。

---

### 第二维：全栈的系统工程与构建能力

这是Agent落地的骨架，要求比传统全栈更宽的技能广度。

-   **Agent专用基础设施构建**：能将LangChain、OpenAI Agents SDK等框架封装为内部工具，并集成外部Agent产品（如Claude Code）。这需要系统编程的去胶合能力。同时，要掌握Docker/K8s，确保Agent在复杂任务中运行在稳定、可复现的沙盒环境里。
-   **高性能与前端可视化能力**：Agent系统的交互延迟至关重要，因此可能需要用Rust来编写核心链路。另外，Agent的“不可观测性”是致命问题，必须能用TypeScript/JS开发调试工具，将每次任务拆解、工具调用等决策过程可视化，以快速定位失败步骤。
-   **工具定义与API设计能力**：Agent的能力上限由其工具决定。需要设计简洁、鲁棒、让模型容易理解的API和工具描述方案，使其像乐高积木一样能被Agent可靠编排和调用。

---

### 第三维：以评测为轴的闭环迭代思维

这是驱动Agent持续进化的引擎，将模型认知和系统工程串联起来。

-   **严谨的评测体系设计能力**：要能从真实场景中抽象出可量化、有区分度的多维度评测集。这需要建立自动化判断脚本，将“任务完成度”细化为工具调用准确率、代码可执行性等客观指标。
-   **Bad Case驱动的数据闭环能力**：这是最核心的迭代范式。通过评测和观测发现Bad Case后，能分析根因，并针对性地构造高价值数据（如补齐数据集、边界用例或对抗样本），再将数据反哺给模型训练，形成一个从“发现问题”到“数据修复”的闭环。
-   **系统性的实验与分析能力**：运行对比实验来验证“新的工具描述”或“新的历史上下文管理策略”是否有效，并能分析出改动引起了模型行为的哪方面变化，而不是凭感觉评估。

### 总结：新时代Agent开发者的画像

-   **不再是纯软件工程师**，而是 **模型驯养师+系统建筑师** 的结合体。
-   **核心工作流变了**：从 产品经理 -> 需求 -> 代码，转变成了 **深度使用 -> 发现边界 -> 构建数据/评测 -> 优化框架 -> 推动模型进化**。
-   **核心能力可以归结为三点**：
    1.  **读心**：能读懂模型的“脑回路”。
    2.  **搭台**：能用全栈技术为模型搭建稳固、可观测的舞台。
    3.  **探路**：能用数据和评测为模型进化指明方向。

这就是你在那两份JD背后，能看到的同一个Agent开发者新物种的全貌。

传统全栈开发与Agent开发者最大的区别在于：**前者构建的是确定性系统，后者则是在“驯养”一个概率性的、非确定性的智能体，并围绕它构建一整套工程体系。**

这个根本差异，带来了思维方式、核心焦点和技能栈上的全面革新。以下从六个维度来拆解：

---

### 一、核心思考维度：从“逻辑实现”变为“概率驯养与交互设计”

-   **传统全栈**
    -   **思维模式**：在确定性领域工作，输入决定输出，Bug是逻辑错误，修复方式是改代码。
    -   **核心关注**：业务流程的代码实现、数据结构、性能优化。
    -   **人机交互**：基于规则的图形界面，用户点击按钮，代码执行预设动作。

-   **Agent开发者**
    -   **思维模式**：在非确定性领域工作，同样的输入可能产生不同结果，Bug是模型的“认知偏差、幻觉或规划断裂”，修复方式可能是调整指令、优化工具描述或构造数据反哺训练。
    -   **核心关注**：如何通过设计上下文、指令和工具，来“引导”模型在概率空间中输出符合预期的推理和行动。
    -   **人机交互**：核心交互变为“自然语言对话+智能体行动”，你的任务是设计高效、防出错的交互循环。

---

### 二、系统架构能力：从“三层架构”变为“训推测一体化的Agent生命体”

-   **传统全栈**
    -   **架构视图**：典型的前端-后端-数据库三层结构，边界清晰。
    -   **构建重点**：RESTful API、微服务、数据库设计、高并发处理。
    -   **生命周期**：开发 -> 测试 -> 部署 -> 维护。

-   **Agent开发者**
    -   **架构视图**：构建一个**“数据->训练->推理->评测->数据”的飞轮系统**。架构中新增了“模型层”这个非确定性组件，以及“评测层”和“数据工厂层”。
    -   **构建重点**：
        1.  **Agent脚手架**：封装工具调用、记忆管理、多轮交互的框架。
        2.  **数据工厂**：自动化构造高质量训练语料的流程。
        3.  **评测平台**：构建沙盒环境，实现多维度、自动化、可视化的评分系统。
        4.  **模型训练链路**：与强化学习（RL）等训练流程对接，实现数据反哺。
    -   **生命周期**：**评测和数据的持续迭代才是核心生命力**，取代了传统的一次性部署。

---

### 三、核心工作流的重构：以“评测-数据”为轴心

-   **传统全栈**
    -   **驱动模式**：需求驱动。产品经理定义功能 -> 开发实现 -> QA测试 -> 上线。
    -   **核心工具**：IDE（集成开发环境）、Postman、DevTools、日志系统。

-   **Agent开发者**
    -   **驱动模式**：**Bad Case驱动**。重度使用 -> 深度评测 -> 发现模型能力边界或失败模式（Bad Case） -> 分析根因 -> 构造靶向数据（补齐/对抗） -> 反哺模型训练或调整工程策略。
    -   **核心工具链**：除了传统工具，还必须包括：
        1.  **深度评测工具**：用于构建场景、跑分、对比不同模型能力。
        2.  **轨迹与调试工具**：能可视化模型每一步的“思考-工具调用-结果”，这是必需的“显微镜”。
        3.  **数据构造与标注平台**：将Bad Case转化为训练数据的工程化流水线。

---

### 四、软件质量的终极衡量标准：从“无错”到“可信”

-   **传统全栈**：**测试覆盖率**是核心理念。衡量代码是否正确、稳定、安全。
-   **Agent开发者**：**评测通过率**是核心标尺。衡量Agent这个系统的综合能力，包括：
    -   **任务完成度与成功率**：是否最终解决了问题。
    -   **工具调用准确率**：指令转化为工具操作的正确性。
    -   **交互步数与效率**：是否能用最优路径完成任务。
    -   **鲁棒性与可靠性**：面对意外情况、长程任务时的稳定性。
    -   **可观测性与可调试性**：这是保障系统不被“黑盒化”的前提。

---

### 五、技能栈的演进：工具的本质变了

-   **新硬件能力**：
    -   **Rust**：在Agent开发中，其出现是为工具的底层、高性能部分（如沙盒环境、仿真器对接、数据处理核心）提供系统级支持，这在传统后端选型中不常见。
-   **新软件能力**：
    -   **前端（JS/TS）**：方向从用户界面转向**开发“内部调试可视化工具”和“评测结果仪表盘”**，核心是为开发者自己或算法团队提供服务。
-   **核心能力的代际差异**：
    -   **传统全栈**：核心技术是并发、缓存、数据库、前端框架等。
    -   **Agent开发者**：新增了致命的技术栈：**提示词工程、检索增强生成（RAG）、Agent架构模式（ReAct等）、工具调用协议、强化学习数据处理、模型能力边界感知**等。

---

### 六、角色的终极定位

-   **传统全栈工程师**：是信息系统的**建筑师与建造者**，关注代码的确定性逻辑。
-   **Agent开发者**：是智能体系统的**建筑师、驯养师与教练**。你不仅搭建它运行的环境（身体），设计它学习的数据（教材），还定义它能力的评测标准（考试），并不断基于评测结果优化数据和环境，让它变得更强大、更可靠。

所以，成为Agent开发者，并不是要丢掉全栈的功底（工程能力是基石），而是在此之上，叠加一整套**面向非确定性智能体的设计、评测、数据和迭代思维**。这是一种根本性的范式跃迁。
