# Think and Make：Agent时代精力的重分配

## 框架判断

- 阅读深度：Read Normally
- 保存建议：保存
- 框架定位：L2.5 适应层-人与组织；副层级：L0 方法论层、决策层
- 对应活问题：Q1 通用智能体何时真正接管白领工作流？Q3 AI 重塑下，家庭与教育的最优策略是什么？Q4 AI 原生组织到底长什么样？
- 有用之处：文章给了一个简单但可操作的个人适应模型：Agent 时代的执行带宽被放大，人的精力应从亲手执行迁移到目标定义、上下文配置、质量判断、工作流设计和复盘沉淀。
- 框架贡献：这是 PACT / 小实验观点在 Agent 工作法里的具体化：不是少做事，而是把 Make 从低层执行升级为编排式执行；把 Think 从空想升级为围绕真实交付的系统设计和复盘。
- 框架更新：个人使用 Agent 的关键不是 70% Make / 30% Think 或 30% Make / 70% Think 的固定比例，而是形成 Make -> Think -> 系统化 Make 的闭环。每一段 Think 都要绑定可观察的 Make，本质上就是让思考持续回到小行动和反馈。
- 噪音风险：文章主要是经验判断，不是数据研究；“未来三年 50/50 最优”这样的比例是启发式，不宜当作严格预测。
- 后续读法：重点吸收“低层执行压缩、高层执行升值”和“五类人的迁移风险”；不要纠结具体比例。

## 内容归纳

核心观点：AI Agent 出现后，个人成长中“思考 vs 执行”的旧模型需要重校准。执行仍然重要，但执行形态变成定义目标、拆约束、配置上下文、让 Agent 先跑、再由人判断、修正、整合和交付。

关键要点：

- 过去的执行是亲手查资料、写代码、做表格、写报告、发邮件、整理结论；现在越来越多执行会变成编排 Agent 和验证输出。
- 新问题不是“多思考还是多执行”，而是“当执行被 Agent 放大后，我应该把自己放在工作链条哪一层”。
- 作者认为未来三年个人时间分配会从 70% Make / 30% Think 迁移到 50% Make / 50% Think；少数有深厚领域积累和反馈渠道的人可走到 40% Make / 60% Think。
- Make 不再只是亲手做完任务，而是编排式执行：编排 Agent、设计工作流、验证输出、完成最终交付。
- Think 也不是坐着空想，而是判断什么值得做、设计什么系统来做、复盘 Agent 为什么做错，并把经验沉淀成更强工作流。
- 纯执行者风险最大，因为重复执行、规则处理、初级分析和信息搬运会被 Agent 压缩，议价权下降。
- 70% Make / 30% Think 的人仍然强，但如果只把 AI 当加速器，没有重写工作方式，就会错过杠杆迁移。
- 50% Make / 50% Think 的核心优势是闭环：每次 Make 变成下一次 Think 的材料，每次 Think 又变成下一次 Make 的系统。
- 30% Make / 70% Think 有更高上限，但只适合有判断力、领域积累和外部反馈渠道的人；否则容易变成高质量拖延。

## 正文摘录

过去几年，我一直用一个很粗糙但有效的模型理解个人成长：有些人主要在做，有些人主要在想。执行型的人能不断产出，思考型的人能不断积累方向感。理想状态，大概是二者兼具。

AI Agent 出现以后，这个模型需要重新校准。

原因不复杂：执行仍然重要，只是执行的形态变了。

以前的执行，是你亲手查资料、写代码、做表格、写报告、发邮件、整理结论。现在越来越多执行，会变成另一种动作：你定义目标，拆出约束，配置上下文，让 Agent 先跑一轮，再由你判断、修正、整合、交付。

于是问题也跟着变了。过去我们常问：我应该多思考，还是多执行？

现在更值得问的是：当执行被 Agent 放大以后，我应该把自己放在工作链条的哪一层？

我的判断是：未来 3 年，最优的个人时间分配，会从过去的 70% Make + 30% Think，逐渐迁移到 50% Make + 50% Think。少数已经有深厚领域积累、判断力和外部反馈渠道的人，甚至可以走到 40% Make + 60% Think。

这里的 Make，不再只是亲手把任务做完。它更接近编排式的执行：编排 Agent、设计工作流、验证输出、完成最终交付。

这里的 Think，也不只是坐在那里想。它更接近复合思维：判断什么值得做，设计什么系统来做，复盘 Agent 为什么做错，再把一次经验沉淀成下一次更强的工作流。

## 一、原来的时间分配为什么失效了

在没有 Agent 的时代，一个人的产出很大程度受限于自己的执行带宽。

你一天能写多少代码、读多少材料、做多少分析、回多少消息，都有清晰的生理上限。于是 70% 执行 + 30% 思考是一种很强的默认策略：做得多，反馈多，学习快，成果也可见。

Agent 改变了这个约束。

麦肯锡 2025 年的全球 AI 调研得出如下结论：AI 高绩效组织的区别，除了用了更多模型，更重要的是主动重写 workflow。换句话说，价值正在从“我会问 AI 一个问题”，进入“我能把一段工作改造成 AI 可以持续参与的系统”。

这就是原模型失效的地方：过去的瓶颈在执行端，现在瓶颈开始往上游移动。

低层执行会被压缩，高层执行会变得更值钱，包括：

- 把模糊目标翻译成 Agent 能执行的任务。
- 给 Agent 足够上下文，同时控制噪声。
- 设计检查点，让错误在早期暴露。
- 对输出做质量判断，避免照单全收。
- 把一次成功流程固化成下一次可复用的系统。

这些动作看起来仍然属于执行，但实际上已经接近更顶层的设计。

## 二、五种人的重新排序

如果把人按 Think / Make 分成五类，Agent 时代的排序会发生变化。

### 1. 95% Make，5% Think：最危险

这类人的优势曾经是勤奋、响应快、能扛活。但如果他的 Make 主要是重复性执行、规则性处理、初级分析、搬运信息，那恰好落在 Agent 最擅长接管的区域。

危险不一定表现为“AI 立刻取代这个人”。更常见的变化，是议价权下降。

原来老板需要你，是因为这些事必须有人做。现在这些事可以由 Agent 做一版，再由更少的人审核。于是纯执行者会被迫卷速度、卷成本、卷可用时长，而这些恰好都不是人类的强项。

这类人的自救方式，是尽快从“任务承接者”升级成“任务定义者”。

### 2. 70% Make，30% Think：仍然很强，但不再是最优

这类人在过去十年非常强。他们能产出，也会复盘；能交付，也有方向感。

Agent 时代，他们依然会比大多数人强，因为他们有真实反馈，不会陷入空想。问题在于，如果他们仍然把大量时间用在可以被 Agent 承接的亲手执行上，就会错过杠杆迁移。

他们最大的风险，是误以为自己已经足够高效。

一个典型信号是：他每天用 AI，但只把 AI 当加速器，没有进一步重写自己的工作方式。

比如：

- 用 AI 帮忙写代码，但没有沉淀项目级 coding workflow。
- 用 AI 写文档，但没有形成自己的研究、引用、审核流程。
- 用 AI 查资料，但没有建立事实核查和来源分层。
- 用 AI 处理琐事，但没有重新设计自己每周的产出系统。

这类人需要的升级，是把 Think 的比例提高到足以重新设计 Make。

### 3. 50% Make，50% Think：新的最佳平衡点

作者认为未来三年，综合表现最好的，大概率是这一类人。

他们会继续交付，而且交付得更多，因为 Agent 放大了执行带宽。与此同时，他们会把省下来的时间投入更高密度的思考：选题、判断、系统设计、复盘、工作流沉淀。

这类人的核心优势是闭环。

每次 Make 都会变成下一次 Think 的材料，每次 Think 又会变成下一次 Make 的系统。

这种人会越来越像一个小型组织：他本人负责战略、审美、判断、质量；Agent 群负责搜索、草拟、编码、对比、测试、整理。

### 4. 30% Make，70% Think：上限更高，但风险也更高

Agent 确实让这类人更有竞争力了。

过去，一个人如果 70% 时间都在思考，很容易落地太慢。现在 Agent 可以帮他把想法快速变成 demo、草案、原型、实验，所以高思考比例不再像以前那么奢侈。

但这个策略只适合少数人。

它要求你已经有足够强的判断力、领域积累、外部反馈渠道。否则 70% Think 很容易退化成高质量拖延：每天都在优化框架、重写路线、构思宏大系统，但没有任何东西进入真实世界。

这类人要保留一个硬约束：每一段 Think，都必须绑定一个可观察的 Make。

## 与 PACT 的关系

这篇文章不构成新的独立方法论，更像 PACT 在 Agent 时代个人生产率上的一个应用：

- Purposeful：先判断什么值得做，而不是因为 Agent 能做就做。
- Actionable：把模糊目标翻译成 Agent 能执行的小任务。
- Continuous：持续把一次交付复盘成下一次更强的工作流。
- Trackable：用可观察的 Make 检验 Think，而不是停留在框架优化。

因此它适合作为 [[工具/AI小实验操作卡]] 和 L2.5 人机分工的案例材料，而不是另起一个并列原则。
