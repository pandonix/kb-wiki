## 框架定位

- 层级：L1 技术工程化 + L2.5 组织适应
- 时间尺度：现在到 2 年
- 对应问题：Agent 什么时候能从“会做题的优等生”变成“能进企业流程的员工”？

## 核心判断

benchmark 是能力筛选，不是生产验收。

生产 Agent 的评估对象不应只是任务完成率，而应包括：

- 行为是否可测
- 链路是否可观测
- 失败是否可回放
- 成本是否可解释
- 权限和安全是否可控
- 人工审查与修复成本是否被计入
- 责任是否可追溯

## 有用之处

- 它区分了“高分 Agent”和“可部署 Agent”。受控任务里的高完成率，不能直接推出真实企业流程里的可用性。
- 它把 Agent 生产评估拆成三段：
  - 上线前：行为测试、eval 覆盖、测试规格、发布门禁
  - 运行中：工具调用、模型路由、延迟、token 消耗、成本、容量错误、链路观测
  - 事故后 / 组织层：失败回放、人工审查、修复成本、工具切换成本、开发者信任
- 它提醒：Agent 落地瓶颈不只是模型能力，而是企业流程可控性、工程观测体系和组织验证成本。

## 应用场景

- 数字分身：不能只看 demo 是否像人、是否能回答问题，还要看账号权限、审批链路、失败回放、人工接管和责任边界。
- Agent 平台：需要从“能调用工具”升级到“可观测、可回放、可控成本、可追责”的生产体系。
- 企业 AI 项目验收：不要只验收效果演示，要验收上线前测试、运行中观测和事故后复盘能力。
- 团队管理：AI 提效要把 review、修复、工具切换、信任损耗等隐性成本算进去。

## 可沉淀规则

Agent 进入企业生产后，真正的验收对象不是“它能不能做完一次任务”，而是“它能否在真实权限、真实数据、真实成本和真实责任链里稳定工作”。

从优等生到好员工，中间差的不是又一个 benchmark，而是一套生产评估与组织接管机制。
