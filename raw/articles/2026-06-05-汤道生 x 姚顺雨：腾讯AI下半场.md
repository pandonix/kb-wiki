## 正文

刚收到这篇对谈实录，是腾讯集团高级执行副总裁、云与智慧产业事业群 CEO 汤道生和腾讯首席 AI 科学家姚顺雨在北京国家会议中心展开的一次对谈。

### 01. 做模型和产品的第一性原理是什么？

**姚顺雨定义"下半场"**：

> 去年之前 AI 发展了几十年，核心是寻找解决问题的方法；但预训练和后训练成熟后，我们有了"万能锤子"，反而更难的是寻找值得解决的好问题。

**加入腾讯的两个原因**：

1. **context 优势**——AI 下半场最重要的是 context。模型越来越擅长把复杂输入变成输出，竞争壁垒转移到最原始的输入端：你知不知道这个人在干什么，知不知道企业的各种信息。
2. **文化**——腾讯是坦诚、trust-based、low ego 的组织。第一次跟总办成员聊天，大家非常诚实，不掩盖问题。这种文化对长期做 AI 非常重要。

**AI 组织应建成的"三角形"**：

- **foundation** —— 预训练 + 后训练。资源要充足，做事方式要正确。
- **product** —— 把技术落地为价值。需要有产品 sense 的人。
- **frontier** —— 探索新研究范式、新机会。姚顺雨承认"中国今天所做的前沿探索不够多"。

### 02. Co-Design：模型和产品如何深度协同？

**Co-Design 三要素**：

1. **模型本身扎实**——预训练是产品无关的通用基础，必须 solid；后训练要摒弃刷榜思维，构建基于真实产品场景的评估体系。
2. **建立信任**——这是最难的部分。模型团队希望能力越强越好，产品团队希望精准满足用户需求。解决方式：换位思考 + 深度绑定。腾讯的具体动作：混元团队派出后训练核心骨干支持元宝后训练工作，即使预训练还没准备好也优先保障元宝。
3. **充分利用 LLM 的泛化性**——Coding Agent 需要的不仅是 coding 数据，还需要聊天、推理、指令遵循等多种能力。产品和模型能力可相互迁移。

**汤道生补充 Co-Design**：

> 关键是"对齐"——产品方向、模型数据标注、Eval 颗粒度、alignment……如果没有对齐，模型行为会不可预测。

**关于 Eval（评估体系）**：

- 第三方 benchmark 有价值，但非常容易 overfitting
- 真实世界 Eval 能发现：① 榜单没暴露的底线问题；② 真实 Prompt 分布（更模糊、多轮）；③ 推进新研究方向（如长上下文）
- Hy3 Preview 发出的主要目的之一就是获取真实反馈，修复后再发正式版

**汤道生总结产品第一性原理**：

> 最终还是用户到底有什么需求、怎么解决他的痛点。但在 AI 时代，产品形态从"功能菜单"变成"开放服务"——产品方也不知道用户会问什么，要充分利用模型理解需求 + 调用工具。

**研发流程重构**：

- 工程师不再只是写代码，而是指挥 AI 的主导者
- 测试左移：评测、alignment 前置到需求阶段
- 角色融合：PM、工程师、设计师、测试边界变模糊

### 03. Agent：技术怎么走、产业怎么落地？

**Coding Agent 是基础能力**：

- 姚顺雨：Coding Agent 有点像预训练，是不得不做的事情
- Coding Agent 本质上图灵完备——能控制 file system + container = 完整自动化系统
- 即使只想做 Coding，也需要聊天、推理、搜索、指令遵循等综合能力

**Token 焦虑的回应**：

> 性能 > 一切。很多人最后发现用 Opus 比用更差模型更省钱，因为更快做对、省了人的精力。
> 在中国，性价比首先是性能；如果性能不好，性价比无从谈起。

**Agent 产品形态**（汤道生）：

> 不同场景有不同 Agent。重要的是给模型提供：工具、skills、记忆、用户 preference、context。
> 模型能力越强，Agent 设计可以越简化。

**AI 时代组织特征**：

- **3-5 人精英小团队**——扁平化、围绕一个领域攻坚、充分试错
- **角色融合**——工程师更像有想法的 leader，驱动多个 Coding Agent
- **测试与对齐左移**——需求、架构、评测一起做

### 04. 行业研判：AI 新的机会在哪里？

**姚顺雨的两个判断**：

1. **AI 是短期游戏还是长期游戏？**——判断是长期游戏。"下半场才刚刚开始，我不认为 ChatGPT 和 ClaudeCode 会是唯一的 super App。"
2. **AI 是更线性还是更多元？**——判断是更多元。"Coding Agent 刚起步；多模态、具身智能……还有很多新事情正在发生。"

类比：今天像是 70 年代 PC 刚产生的时候。

> 下半场最重要的事情：能不能诚实面对自己、能不能 Be Real、能不能看到 feedback 然后改变、能不能保持耐心。

**汤道生收尾**：

> 这是一个长跑。AI 需要 Context——腾讯过去多年不同产品在不同赛道的积累，都可以为模型提供有用的 context。
> 我们是很多业态的公司，有的地方会快一点，有的地方会慢一点，也请大家多给我们提醒。

## 凇哥批注

把 A2 推回腾讯组织现实，会看到姚的 Co-Design 第三点（"数据网络化"）撞上腾讯最深的结构事实：**优势的来源和障碍是同一个**。

### 1. "数据网络"在腾讯是账面上的，不在管道里

姚的第三点暗含一个前提：数据可以在产品之间自由流动、汇到中央模型。但腾讯的 DNA 是 **赛马 + BG 自治 + 数据即护城河**。让一堆以 P&L 为本位的 BG，把数据上交给一个服务于元宝、还在跟自己抢 C 端 AI 心智的中央模型团队——这跟它们本能激励是反的。

### 2. 微信的选择是反向的：AI 进我的墙里来

马化腾给出的两类 Agent（通用型元宝 + 嵌入微信生态的"生态型 Agent"）+ "原子化组件" + "AI 全家桶未必是大家都喜欢的"——这是分布式架构，不是中央集权。翻译：微信要的是 AI 进我的墙里来，不是我的数据出去喂中央模型。

### 3. 2025-12 集权 = 制度性承认"自发信任没发生"

腾讯新成立 AI Infra 部、AI Data 部、数据计算平台部（"把分散的发电厂整合成国家电网"），姚直接向刘炽平汇报。一个做模型的人需要总裁级汇报线，是因为要从微信这种 BG 诸侯手里抽数据、抽算力——没有最高层政治授权根本做不动。**这条高汇报线，本身就是为了对抗这个掣肘而设计的。**

### 4. 两种 trust 维度，姚把它们混成了一个

- **纵向、文化信任**：公司对人才的 trust + low ego + 长期主义。腾讯确实有，姚体验到的浓度是公司最高档。
- **横向、组织间信任**：BG ↔ BG，愿不愿意把数据、算力、eval、用户交出去。Co-Design 要的恰恰是这一种。

**姚的"基于 trust 而非 metric"在横向这根轴上几乎是反的**。腾讯横向的底层机制是赛马，赛马本质上是个 metric 机制（让数据/市场来裁决谁赢）。微信本身就是赛马赛出来的。汤在 CSIG 930 之后专门宣布"不再赛马"，恰恰说明默认状态是赛马、是内耗，横向信任不是自动存在的。

腾讯组织变革史就是一部"横向 trust 不够 → 顶层强制合并 → 几年后再来一次"的循环：2005 BU、2012 518、2018 930、2025 AI 集权，每 6-7 年一次。

### 5. 汤的"对齐" = 同一个 gap 的另一视角

姚把 trust 当前提（默认既成），汤把 trust 当产出（必须被制造出来——靠对齐流程、利益绑定、顶层强制）。前者把信任当底色，后者把信任当工序。**人最容易犯的错，是把自己亲身体验到的那种信任（往往是纵向的、被给予的）误当成自己真正要依赖的那个维度（横向的、要去争取的）也同样成立。**

### 6. 可证伪试金石：微信会不会给混元

未来 12-18 个月内可观察的硬指标：

- 微信关系图谱 / 私域聊天是否进入混元预训练（几乎肯定不会——合规 + 竞争）
- 2025-12 集权之后，是否有 BG 级数据真正被收归中央（部分会，但会有剧烈博弈）
- WorkBuddy 接入的"混元/DeepSeek/GLM/Kimi/MiniMax"中，混元的实际份额是否上升
