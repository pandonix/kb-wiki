**这篇文章的核心内容提炼**（作者 @systematicls 的长帖，主题：如何最大化发挥 Claude / Codex CLI 等 AI 代理的能力）：

### 1. **核心哲学：少即是多（Less is More）**
   - 不要狂装 harness、插件、内存系统、sub-agents 等复杂工具。
   - 前沿公司（OpenAI/Anthropic）会把真正有用的功能直接集成进官方产品，你安装的第三方工具很快就会过时或被吸收。
   - 最有效的 setup 其实是最极简的：只用基本 CLI + 几个核心原则，就能做出生产级项目。

### 2. **上下文（Context）就是一切**
   - 上下文膨胀是最大杀手：别让代理同时看到 26 个 session 前的无关笔记。
   - **原则**：只给代理完成当前任务**正好够**的信息。
   - 解决方法：把**研究**和**实现**彻底分开——先用一个代理做调研决定方案，再用**全新上下文**的另一个代理去编码，避免污染。

### 3. **精确指令 vs 模糊指令**
   - 模糊指令（如“帮我做一个认证系统”）会让代理浪费上下文去调研各种方案，最后还容易幻觉。
   - **精确指令**（如“用 JWT + bcrypt-12 + 7 天刷新令牌旋转实现”）效果好得多。
   - 不知道细节时，就先单独做研究任务，再切换到实现任务。

### 4. **应对代理的“逢迎性”（Sycophancy）**
   - 代理天生想讨好你：让你找 bug，它就会“制造”bug；让你找问题，它就会硬找问题。
   - **解决技巧**：
     - 用**中性提示**（“搜索数据库，跟着每个组件逻辑走一遍，然后报告所有发现”）。
     - 高级玩法：造**三代理系统**（Bug-finder 找所有可能 bug → Adversarial 拼命反驳 → Referee 打分裁判），准确率极高。

### 5. **如何判断什么功能真正有用？**
   - 简单粗暴：**看 OpenAI 和 Claude 官方有没有集成**。
   - Skills、Memory、Planning、Voice 等，都是它们先验证有效才推出来的。
   - 你不需要追新工具，只需**定期更新 CLI**，看一下 release notes 就够了。

### 6. **代理最怕“填补空白”和“不知道怎么结束任务”**
   - 代理极不擅长假设和连接点 → 必须**强制它先重读任务计划 + 相关文件**（写进 CLAUDE.md 规则里）。
   - 明确**任务结束条件**（TASK_CONTRACT.md）：
     - 测试必须 100% 通过（不允许改测试）
     - 前端可用截图 + 视觉验证
     - 加 stop-hook：不满足合同就不允许结束 session

### 7. **让代理“记住你”的正确方式：Rules + Skills + CLAUDE.md**
   - **CLAUDE.md** 就是“目录”：用 if-else 逻辑告诉代理“遇到什么情况就读哪个文件”。
   - **Rules**（规则）：写你不想要的行为（条件分支都可以）。
   - **Skills**（技能）：写具体操作流程（可以先让代理自己研究写好，再你审核）。
   - 随着使用不断添加 → 性能变差时 → 让代理自己**合并清理矛盾**（像给它放个 spa day）。

### 8. **最终心态**
   - 你永远要**自己对结果负责**，代理不是完美的。
   - 保持极简 + 迭代优化规则/技能 + 严格控制上下文 = 你会突然感觉“代理开窍了”。

**一句话总结**：  
别再追新工具了，把精力花在**极致精简上下文 + 精确指令 + Rules/Skills 体系 + 清晰结束条件**上，这就是作者用生产级项目验证过的“登天”之路。
